# 抖音手势控制（Edge 扩展）

用摄像头识别手势，控制抖音网页版的视频切换、倍速与暂停。画面只在本地处理，不上传。

---

## 安装

1. 打开 `edge://extensions`
2. 打开左下角「开发人员模式」
3. 点「加载解压缩的扩展」，选择本目录（`extension/`）
4. 打开 https://www.douyin.com/ ，点工具栏扩展图标 → 打开开关
5. 首次会请求摄像头权限，点「允许」

## 手势

| 手势 | 动作 |
|---|---|
| 比 1（只伸食指） | 下一个视频 |
| 比 2（食指 + 中指） | 上一个视频 |
| 竖大拇指 | 快进：1× → 2× → 4× → 1× |
| 五指张开 | 暂停 / 继续 |

手势需保持 0.3 秒；触发后同姿势不再重复生效，需收手或换手势。

页内快捷键：`Alt + Shift + G` 开关。

## 状态提示

页面右下角有一个小胶囊：

| 显示 | 含义 |
|---|---|
| 灰点「手势 关」 | 未开启 |
| 青点「手势 开」 | 已开启 |
| 青色文字「识别到 1 · 213ms」 | 正在保持，数字是已保持时长 |
| 琥珀色文字 | 异常提示：手太靠边 / 离镜头近一点 / 切换失败 |

## 实现结构

```
inject.js   （MAIN world）
  摄像头 → MediaPipe Hands → 手势状态机 → postMessage
content.js  （隔离世界）
  接收手势 → 定位视频与滚动容器 → 执行动作 → 状态胶囊
popup.html/js
  开关（写入 storage + 通知内容脚本）
```

### 为什么驱动要「自适应 + 自校验」

抖音的 CSS 类名是构建时混淆的（如 `yP5MkONE llbV_Rqp`），写死选择器必然随版本失效。所以采用三级降级：

1. 从当前视频元素沿祖先链找第一个「可滚动且溢出」的容器；
2. 找不到则在全页找「包含 video 且溢出最多」的容器；
3. 仍不可滚则退到文档滚动容器。

每次执行后比较 `scrollTop` 是否真的变化，未变化则回退为派发 `ArrowDown/ArrowUp` 键事件，再失败才报「切换失败」。

### 为什么识别跑在页面主世界

扩展页面受 MV3 CSP 限制，无法从 CDN 加载 MediaPipe（需把 ~9MB 模型打进包里）。当前实现把识别注入页面上下文，代价是**摄像头权限提示会显示 douyin.com**，而不是扩展名。后续版本会改为扩展内打包 + iframe 承载。

## 已知限制

| 限制 | 说明 |
|---|---|
| 摄像头权限提示归属 douyin.com | 见上，暂无法规避 |
| 未登录只能进「精选」页 | 抖音在未登录时会跳转 `/jingxuan`，该页是卡片列表，不是全屏短视频流 |
| 多人同框 | 只取检测到的第一只手 |
| 逆光 / 暗光 | 关键点抖动，命中率下降 |
| 摄像头被占用 | 会议软件等占用时会报「摄像头被拒绝」 |

## 排障

| 现象 | 处理 |
|---|---|
| 扩展图标点了没反应 | 确认当前标签页是 `https://www.douyin.com/`，刷新页面重试 |
| 状态一直是「正在请求摄像头」 | 检查是否有其他程序占用摄像头（会议软件、其他浏览器标签） |
| 提示「识别模型加载失败」 | 需要访问 `cdn.jsdelivr.net`，检查网络或代理 |
| 手势识别到但没切视频 | 看胶囊是否显示「切换失败」；若是，说明该页面结构未被适配，需反馈 |
