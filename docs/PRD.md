## 1. 一句话定义

在 Edge 里用摄像头识别手部动作，用**手掌上下滑动**代替滚轮，控制抖音网页版切换视频。

---

## 2. 背景与动机

**现状痛点**：抖音网页版只有键盘、滚轮、点击三种输入方式。连续刷视频时手必须一直搭在鼠标或键盘上，姿势固定、动作重复。

**已有方案的缺口**：

- 手机端不存在这个需求（原生就是滑动）
- 通用的浏览器手势扩展（如各类 "hand gesture scroll"）适配的是普通页面滚动，而抖音是**虚拟列表 + scroll-snap**，直接滚动大概率无效
- 没有专门针对 douyin.com 的实现

**为什么值得做**：

| 维度 | 判断 |
|---|---|
| 技术栈 | 轻。MediaPipe WASM + MV3，无后端、无服务端成本 |
| 可验证性 | 强。延迟、帧率、误触发率、识别率都是可测的硬指标 |
| 风险集中度 | 高。90% 的不确定性集中在「抖音 DOM 能否被程序化驱动」这一件事上 |
| 失败成本 | 低。最差结果是做成一个骨架识别 demo，代码不浪费 |

---

## 3. 目标与非目标

### 3.1 目标（按优先级）

| 优先级 | 目标 |
|---|---|
| P0 | 手不碰键鼠，能连续切换视频，全程不中断 |
| P0 | 端到端延迟 ≤ 300ms（手势结束 → 画面切换） |
| P0 | 静止误触发 ≤ 1 次 / 10 分钟 |
| P1 | 随手可开关，不用时摄像头必须真正关闭 |
| P2 | 识别结果可视化，便于自己调参和排查 |

### 3.2 非目标（明确不做）

| 不做的 | 原因 |
|---|---|
| 点赞 / 收藏 / 关注 / 评论 | 误触代价高，属于社交动作，可能触发账号风控。滑动误判最多多刷一条 |
| 音量 / 进度条手势 | 原生方向键和空格更快更准，属负收益 |
| 移动端 / iOS | 手机自带滑动，无需求 |
| 通用网页手势控制 | 首版只服务 douyin.com，做通用会稀释掉对单站点的适配深度 |
| 账号体系 / 云端同步 / 配置分享 | 单人自用工具，无此需求 |

## 4. 用户与场景

**主要用户**：本人。单人自用，不考虑多用户、不考虑分发上架。

**典型场景**：
晚上在笔记本前，手自然放在桌面或腿上，视线在屏幕上，用手掌上下挥动切视频。

**明确不适用的场景**（不作为设计目标）：

| 场景 | 失效原因 |
|---|---|
| 强背光 / 逆光 | 手部轮廓分割失败 |
| 多人出现在画面中 | 检测到多手时判定不确定 |
| 手部被桌面、被子遮挡 | 关键点置信度低于阈值 |
| 剧烈运动 / 手持设备 | 画面抖动导致位移判定误判 |

## 5. MVP 范围

### 5.1 功能清单

| # | 功能 | 优先级 | 验收标准 |
|---|---|---|---|
| 1 | 手掌上移 → 下一个视频 | P0 | 连续 50 次，成功 ≥ 45 次 |
| 2 | 手掌下移 → 上一个视频 | P0 | 连续 50 次，成功 ≥ 45 次 |
| 3 | 悬浮状态灯（关闭 / 检测到手 / 触发中） | P0 | 三种状态肉眼可区分 |
| 4 | 快捷键开关（`Alt+Shift+G`） | P0 | 关闭后摄像头指示灯熄灭 |
| 5 | 手部预览小窗（可折叠） | P1 | 折叠后不遮挡视频内容 |
| 6 | debug 页（骨架 + FPS + 阈值滑块） | P1 | 实时显示，滑块调整立即生效 |

### 5.2 本版不做

- 第三种手势（握拳暂停等）—— 留到 v1，接口预留
- 设置面板与配置持久化 —— MVP 用常量 + debug 页临时调
- 惯性 / 平滑滚动
- 手势可视化动画、音效反馈

> **刻意约束**：手势数量与调试难度是非线性关系。两个滑动手势已足以验证状态机可扩展性，加到第三个容易陷入「调好一个弄坏另一个」的循环。

## 6. 手势词典

| 手势 | 定义 | 触发动作 | 误判风险 |
|---|---|---|---|
| 手掌上移 | 五指张开、掌心朝摄像头，整体向上位移超过阈值 | 下一个视频 | 中：抬手、挠头可能触发 |
| 手掌下移 | 同上，方向向下 | 上一个视频 | 中：手放下可能触发 |
| （预留）握拳 | 五指收拢保持 N 帧 | 暂停 / 播放 | 低 |

**判定要素**（三个参数共同决定误触与延迟的平衡）：

| 参数 | 作用 | 初值（待调） |
|---|---|---|
| 位移阈值 | 手掌中心移动多少算「滑动」 | 掌宽的 1.2 倍（相对值，抗距离变化） |
| 时间窗 | 位移必须在多长时间内完成 | 400ms |
| 冷却时间 | 一次触发后多久内不再判定 | 800ms |

> 用**掌宽归一化**而不是绝对像素，是为了让人离摄像头远一点、近一点都能用，不用重新调参。

## 7. 交互设计

### 7.1 状态灯

| 状态 | 颜色 | 含义 |
|---|---|---|
| 关闭 | 灰 | 未启用，摄像头已释放 |
| 待命 | 绿（呼吸） | 已启用，未检测到手 |
| 检测中 | 青 | 检测到手，但未达到触发条件 |
| 触发 | 蓝（闪一下） | 刚发出一次切换指令 |

### 7.2 预览小窗

- 位置：右下角，距边 16px
- 尺寸：展开 160×120，折叠 48×48
- 内容：镜像摄像头画面 + 手部骨架线
- 交互：点击折叠 / 展开，可拖动

### 7.3 首次使用引导

1. 点扩展图标 → 弹出授权提示
2. 允许摄像头 → 预览窗出现，提示「举起手掌试试」
3. 检测到第一次成功触发 → 提示消失

## 8. 技术方案概要

| 环节 | 选型 | 关键参数 | 理由 |
|---|---|---|---|
| 扩展形态 | MV3（Manifest V3） | service worker + content script | Edge / Chrome 通用 |
| 手部识别 | MediaPipe Tasks `HandLandmarker` | 21 点/手，最多 2 手，WASM + GPU delegate | 帧率与精度平衡最好，模型约 7.8MB |
| 摄像头承载 | 扩展页 iframe + `allow="camera"` | 扩展源授权，不污染页面域 | 避免出现「douyin.com 请求摄像头」的怪异提示 |
| 通信 | `postMessage`（iframe ↔ content script） | 单向事件流 | 简单，无需长连接 |
| 页面注入 | content script | `matches: *://*.douyin.com/*` | 标准做法 |
| 滚动驱动 | **待 M1 探测确定** | 见第 10 节 | 三选一，必须实测 |

### 8.1 数据流

```
摄像头帧 → HandLandmarker → 21 关键点
    → 手势状态机（位移 / 时间窗 / 冷却）
    → postMessage → content script
    → 滚动指令 → 抖音视频切换
```

### 8.2 模块划分

| 模块 | 职责 | 可测试性 |
|---|---|---|
| `recognizer.js` | 关键点 → 手势标签 | 纯函数，输入坐标序列输出标签，可单测 |
| `gesture-state-machine.js` | 时序判定、防抖、冷却 | 纯状态机，喂时间戳序列可测 |
| `injector.js` | 手势事件 → DOM 操作 | 需真实 DOM，jsdom 或集成验证 |
| `debug.html` | 可视化与调参 | 人工验证 |

## 9. 验收指标

| 指标 | 目标 | 测量方法 |
|---|---|---|
| 端到端延迟 | ≤ 300ms | 240fps 慢动作录屏，数「手停」到「画面变」的帧数 |
| 单次识别率 | ≥ 90% | 连续 50 次滑动，人工计数 |
| 静止误触发 | ≤ 1 次 / 10 分钟 | 手放桌上不动，看 10 分钟视频计数 |
| 识别帧率 | ≥ 25 fps | debug 页实时显示 |
| 内存增量 | < 300MB | 任务管理器看 Edge 进程组 |

## 10. 风险与对策

| # | 风险 | 概率 | 影响 | 对策 |
|---|---|---|---|---|
| 1 | 抖音滚动容器无法被程序化驱动 | 中 | **致命**（只能做 demo） | M1 先探测，三方案并行验证：容器 `scrollBy` / 派发方向键 / 点击切页按钮 |
| 2 | Edge 对 iframe `allow="camera"` 限制比 Chrome 严 | 中 | 高 | 备选方案：offscreen document 承载摄像头 |
| 3 | MediaPipe 在集显上帧率不足 25fps | 中 | 中 | 降输入分辨率至 320×240；改用 GPU delegate；降低检测频率到 15fps |
| 4 | 误触发率高，实际不可用 | 中 | 高 | 三参数联调（阈值 / 时间窗 / 冷却），必要时加「手掌必须静止 N 帧才开始计时」 |
| 5 | 抖音前端改版导致选择器失效 | 低 | 中 | 选择器集中在一个常量文件，改版时只改一处 |

## 11. 里程碑

| 里程碑 | 内容 | 完成标准 | 预估 |
|---|---|---|---|
| **M1 探测 + 骨架** | 抖音 DOM 探测；扩展能加载；摄像头预览可用 | 能跑出一份「滚动可行性结论」；预览窗能显示画面 | 2h |

## 附录 A：关键决策记录

| 决策 | 选了 | 放弃了 | 理由 |
|---|---|---|---|
| 交付形态 | 浏览器扩展 | 油猴脚本 / 纯本地网页 | 油猴的摄像头权限落在 douyin.com 域，提示怪异；纯本地页碰不到抖音 |
| 手势数量 | 2 个 | 4 个以上 | 调试成本随数量非线性上升 |
| 触发动作 | 视频切换 | 点赞、评论 | 误触代价不对称，只有滑动是「错了也无所谓」 |
| 位移判定 | 掌宽归一化 | 绝对像素 | 抗手与摄像头距离变化，免重调参 |
| 事件合成 | 操作 DOM | 合成键盘事件 | `isTrusted=false` 可能被忽略，DOM 操作更可靠 |

## 附录 B：术语

| 术语 | 含义 |

| Landmark | MediaPipe 输出的手部关键点，21 个/手 |
