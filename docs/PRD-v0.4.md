**版本** v0.4 · **状态** 演示版已实现并验证 · **日期** 2026-11-03

## 0. 一页速览

| 项 | 内容 |
|---|---|
| **一句话** | 在电脑上刷抖音，动动手就能切视频，不用碰键盘鼠标 |
| **核心机制** | 摄像头识别手部姿态，四组「比数字」手势映射为播放控制 |
| **当前形态** | 独立网页演示版（`demo/pose.html`），接入真实摄像头与 MediaPipe，可直接体验 |
| **下一形态** | Edge 扩展，注入抖音网页版，手势直接驱动视频流 |
| **手势数量** | 4 个（切上/切下/快进/暂停） |
| **单次操作耗时** | 约 350ms（保持 300ms + 处理 50ms） |
| **当前阶段** | M1 手势方案验证 ✅ 已完成；M2 抖音 DOM 探测 ⏳ 未开始 |
| **最大风险** | 抖音网页版的滚动容器能否被程序化驱动（未验证） |

## 1. 问题与机会

### 1.1 真实痛点

抖音网页版的操作依赖三种输入：滚轮、方向键、鼠标点击。这三种都需要**手离开当前姿势**才能完成。实际使用中的典型场景：

| 场景 | 现状 | 摩擦 |
|---|---|---|
| 躺着/靠着看 | 手要伸到键盘 | 姿势被打断 |
| 吃饭时 | 手上是油的 | 不敢碰键鼠 |
| 长时间连续刷 | 每 20 秒按一次方向键 | 累积性烦 |
| 看教程类长视频 | 要调倍速、要暂停 | 找控件，视线离开画面 |

### 1.2 现有方案为什么不够

| 现有方案 | 缺口 |
|---|---|
| 抖音自带的键盘快捷键 | 仍然需要碰键盘 |
| 通用手势浏览器扩展 | 识别的是「手掌滑动」，本场景没有对应的滚动容器可驱动；且要求手掌正对镜头挥手，命中率不稳 |
| 触控板/触摸屏 | 需要设备支持，且同样是「手要伸过去」 |

**结论**：这个场景需要的不是「更准的手势识别」，而是**一套为短视频流设计的、误触代价可控的最小手势集**。

## 2. 用户与场景

### 2.1 目标用户

单人、近距离（40–60cm）、有摄像头、用 Edge/Chrome 在电脑上刷抖音。**不假设**用户有特殊硬件或愿意做复杂配置。

### 2.2 采用场景

1. **躺姿刷**：笔记本放腿上或床上桌，手自然放在身体两侧。
2. **边吃边看**：单手操作，另一只手不方便。
3. **长视频调速**：教程、纪录片，需要快进和暂停。

### 2.3 明确不适用的场景

| 场景 | 原因 | 产品应对 |
|---|---|---|
| 多人同框（宿舍、办公室） | 无法确定是谁在控制 | 只取检测到的第一只手，不做多用户区分；文档明示 |
| 强逆光 / 夜间不开灯 | landmark 抖动，命中率骤降 | 界面提示补光；实测暗光下摄像头降帧到 15fps 仍可用 |
| 手被遮挡（桌下、被身体挡住） | 检测不到 | 状态灯显示「未检测到手」，不误判 |
| 手机端浏览器 | 非安全上下文拿不到摄像头 | 不做支持，明确写进限制 |

## 3. 交互模型

### 3.1 手势集

| 手势 | 姿态描述 | 动作 | 误触代价 |
|---|---|---|---|
| **比 1** | 手背朝镜头，只伸食指 | 下一个视频 | 低（多刷一条） |
| **比 2** | 手背朝镜头，食指+中指 | 上一个视频 | 低（回退一条） |
| **竖大拇指** | 拇指外伸，四指收拢 | 快进：1× → 2× → 4× → 1× 循环 | 中（画面速度变化，可再切回） |
| **五指张开** | 五指伸直并分开 | 暂停 / 继续（切换） | 低（再比一次恢复） |

**设计逻辑**：误触代价越低的动作，越允许灵敏；代价高的动作（如点赞、关注）一律不做。

### 3.2 快捷开关

这是本版新增的控制入口，解决「每次开关都要走三步引导」的摩擦。

| 属性 | 规格 |
|---|---|
| 位置 | 右上角常驻胶囊按钮，`z-index` 高于内容层 |
| 状态 | 关闭时灰点 +「手势 关」；开启时青点发光 +「手势 开」 |
| 交互 | 单击即开关，无需二次确认 |
| 首次 | 未看过引导 → 弹三步引导；看过之后 → **直接开关，不再弹** |
| 快捷键盘 | `Alt + Shift + G`，与按钮等价 |
| 状态记忆 | 记住「上次是否开启」与「是否看过引导」，刷新后自动恢复上次状态 |
| 关闭语义 | 立即停止摄像头轨道（指示灯熄灭），释放资源 |

**为什么需要它**：手势控制是「阶段性使用」的功能——开会、视频通话时必须能一键关掉。开关如果藏在菜单里，用户会直接卸载。

### 3.3 状态机

```
                    ┌────────────────┐
       快捷开关/快捷键 │    IDLE 关闭    │  摄像头已释放
                    └───────┬────────┘
                            │ 开启
                            ▼
                    ┌────────────────┐
                    │  ARMED 待命     │◄──────────────┐
                    └───────┬────────┘               │
              识别到 1/2/拇指/张开                     │
             且几何有效（C3 通过）                      │
                            ▼                        │
                    ┌────────────────┐               │
                    │ HOLDING 计时中  │  中断：手势变化 │
                    │   < 300ms      │  或 C3 失败    │
                    └───────┬────────┘               │
                            │ 满 300ms               │
                            ▼                        │
                    ┌────────────────┐               │
                    │ FIRING 触发     │  执行动作       │
                    └───────┬────────┘               │
                            ▼                        │
                    ┌────────────────┐               │
                    │ LOCKED 锁定     │───────────────┘
                    └────────────────┘  收手 / 换手势 / 手离开
```

**锁定是防误触的核心**：触发后同一姿势继续举着不会重复触发，必须先「放下」或「换一个数字」。这一条消灭了「切完视频手一放又切回来」的经典问题。

### 3.4 延迟预算

| 阶段 | 耗时 | 说明 |
|---|---|---|
| 保持确认 | 300 ms | 设计参数，可调 120–800 |
| 模型推理 | 30–60 ms | 15–30fps 下，单帧推理 |
| 动作执行 | < 16 ms | 滚动/调速均为一帧内完成 |
| **合计** | **≈ 350–380 ms** | 目标 ≤ 400ms |

用户感知上，这段时间的「等待」被进度条可视化，不是空等。

## 4. 手势设计原则

这五条决定了为什么是这四个手势，而不是别的。

1. **离散优于连续**。静态姿势（比几）比动态轨迹（划过）稳定得多。相同精度下，前者的失败模式是「没识别到」，后者的失败模式是「识别成别的」——后者更糟。
2. **每个手势必须可自纠**。切错了立刻反比一次就能回来；快进错了再竖一次就降档。没有不可逆操作。
3. **不做需要精确控制的手势**。音量、进度条拖动一律不做——精度需求超过摄像头能力，且原生键盘更快。
4. **不做有社交后果的手势**。点赞、关注、评论、收藏：误触会留下痕迹，代价不可撤销。
5. **任何时候都能退出**。快捷开关必须能在 1 秒内关闭，且立即释放摄像头。

## 5. 判定规格

四条判据同时满足才触发。

### C1 单手可见

MediaPipe Hands 检出至少一只手且 21 点齐全。只取第一只，不做多手融合。

### C2 手势命中

**手指伸直判据**（对食指、中指、无名指、小指）：

```
伸直 ⟺ dist(腕, 指尖) / dist(腕, 指根PIP) > 1.15
```

选比值而非关节夹角的两个理由：与尺度无关（远近都能用）、与旋转无关（手转半侧不失效）。实测取值：伸直 1.3–1.5，弯曲 0.6–0.9。

**拇指判据**（拇指无 PIP 结构，单独处理）：

```
拇指外伸 ⟺ dist(拇指尖4, 食指根5) / 掌宽 > 0.45
```

握拳时拇指压在掌上约 0.2，竖起时约 1.0，区分度充分。

**张开判据**（仅用于「五指张开」）：

```
张开 ⟺ (g1 + g2 + g3) / 3 > 0.28      三者 = 相邻指尖间距 / 掌宽
```

取三者**平均**而非最大值：单根手指抖动不应把「并拢」判成「张开」。

### C3 几何有效性

| 检查 | 阈值 | 不通过时 |
|---|---|---|
| 出框 | 任一关键点落在画面边缘 1.5% 内 | 不触发，骨架变琥珀色，提示「手太靠边 · 往中间挪」 |
| 距离 | 掌宽 < 22px（640×480） | 不触发，提示「离镜头近一点」 |

**为什么必须有这一条**：一次真机录屏里读到 `纵向 +2.11 掌宽`——物理上不可能。追查发现手贴在画面右侧被裁断，掌宽被算小，归一化后的数值全部虚高。所有「除以掌宽」的判据在出框时都会失真，必须前置拦截。

### C4 保持时长

同一手势连续保持 ≥ 300ms，手势一变立即重新计时。

### 参数表

| 参数 | 默认 | 范围 | 调整优先级 |
|---|---|---|---|
| 保持时长 | 300 ms | 120–800 | ① 灵敏度总开关 |
| 冷却 | 1000 ms | 400–2500 | ③ 连续操作间隔 |
| 手指伸直阈值 | 1.15 | 1.02–1.40 | ② 手型差异大时调 |
| 张开阈值 | 0.28 | 固定 | — |
| 拇指阈值 | 0.45 | 固定 | — |
| 出框边距 | 1.5% | 固定 | — |
| 最小掌宽 | 22 px | 固定 | — |

## 7. 异常与边界

| # | 情况 | 表现 | 处理 |
|---|---|---|---|
| 1 | 手出画 | 骨架琥珀色，提示往中间挪 | 拒绝触发 |
| 2 | 手离太远 | 提示离镜头近一点 | 拒绝触发 |
| 3 | 手势不标准 | C2 不亮 | 拒绝触发，不猜 |
| 4 | 触发后不收手 | 锁定，不重复 | 需收手或换手势 |
| 5 | 冷却期内再次比划 | 无反应 | 冷却 1000ms |
| 6 | 摄像头被其他程序占用 | Toast：摄像头被占用（如会议软件） | 引导关闭占用程序 |
| 7 | 用户拒绝授权 | Toast：点地址栏相机图标允许后重试 | 给出具体操作位置 |
| 8 | 没有摄像头 | Toast：没有找到摄像头设备 | 不做降级 |
| 9 | `file://` 打开 | 全屏拦截层 + 两种启动指引 | 阻断，不抛红字错误 |
| 10 | 非安全上下文 | Toast 提示摄像头会被拦截 | 提示用 127.0.0.1 |
| 11 | 页面切到后台 | 帧率骤降或暂停 | 不做特殊处理，回前台自动恢复 |
| 12 | 暂停中切换视频 | 新视频仍处于暂停态 | 符合直觉，暂停是全局状态 |

## 8. 质量门槛

### 8.1 验收指标

| 指标 | 目标 | 测法 |
|---|---|---|
| 单次命中率 | ≥ 95% | 连续比 1 共 40 次，记成功数 |
| 静止误触发 | ≤ 1 次 / 10 分钟 | 手放桌上不动，看 10 分钟视频计数 |
| 端到端延迟 | ≤ 400 ms | 保持 300ms + 处理；慢动作录屏核对 |
| 识别帧率 | ≥ 15 fps | 预览窗实时显示 |
| 切换误触 | ≤ 1 次 / 10 次 | 比 1 ↔ 比 2 来回 10 轮 |
| 内存增量 | < 300 MB | 任务管理器看 Edge 进程组 |

### 8.2 自动化测试（39 项，全通过）

用无头 Edge + CDP 驱动，向页面喂**合成 21 点关键点**，走完整识别流水线，不是只测纯函数。

| 分组 | 覆盖 | 项数 |
|---|---|---|
| 手势判定 | 四手势各归其位；握拳、三指、并拢平掌不触发 | 7 |
| 拇指判据 | 外伸被识别、收拢不被识别 | 2 |
| 几何保护 | 出框标记、太远标记 | 2 |
| 环境 | 摄像头流挂载、MediaPipe 加载 | 2 |
| 状态机 | 保持触发 / 锁定 / 不重复 / 收手解锁 / 换手势再触发 | 6 |
| 新手势 | 快进三档循环、暂停与继续 | 5 |
| 保护生效 | 出框不触发 + 提示、太远不触发、恢复后可触发 | 3 |
| 快捷开关 | 初始态、首次弹引导、跳过即开、二次直达、关闭、刷新自动恢复 | 13 |

### 8.3 手动清单（自动化测不了的部分）

1. 距离 40–60cm，手在虚线框内比 1，看「指型」是否显示「比 1」。
2. 保持 0.3 秒后应切下一个，进度条在切换瞬间走满。
3. 切换后继续举着不动，不应重复触发。
4. 放手再比 2，应回到上一个。
5. 手移到画面最右边，骨架变琥珀、提示出框、不触发。
6. 竖拇指三次，倍速应 2× → 4× → 1× 循环。
7. 五指张开暂停，再比一次继续。
8. 点右上角开关，摄像头指示灯应立即熄灭。

## 9. 技术架构

### 9.1 模块

```
摄像头流 (getUserMedia 640×480)
      │  requestVideoFrameCallback 计数，按帧去重
      ▼
MediaPipe Hands（lite，单帧 ~40ms，15–30fps）
      │  21 点归一化坐标
      ▼
判定层 evaluate()
      ├─ 坐标换算到像素尺度（避免非方形画面拉伸）
      ├─ 五指伸直比值 → ext[]
      ├─ 拇指/张开辅助指标
      ├─ 手势模板匹配 → pose 1/2/3/4
      └─ 出框 / 掌宽有效性
      ▼
状态机（armed → holding → firing → locked）
      ▼
动作层：滚动切换 / 倍速循环 / 暂停切换
```

### 9.2 三个关键实现决策

| 决策 | 原因 |
|---|---|
| 坐标先换算到像素尺度再算角度 | MediaPipe 输出归一化坐标，x 除以宽、y 除以高，非方形画面下直接用会把角度算歪 |
| 送帧按帧序号去重 | 送帧循环按屏幕刷新率跑（60Hz），摄像头只有 30fps，不判重会把同一帧送两遍，白烧 CPU 且帧率读数虚高 |
| 进度条改 JS 驱动 | CSS animation 的时长无法动态修改，改倍速会跳变，无法实现「快进」 |

### 9.3 已知技术债

| 项 | 影响 | 计划 |
|---|---|---|
| 无时间平滑滤波 | 手抖动时指型可能闪变 | 若命中率不达标再加 One Euro Filter |
| 单手限制 | 双手场景只跟第一只 | 符合设计，不修 |
| 模型走公网 CDN | 首屏需 8MB 下载 | 扩展化时改为本地打包 |

| M4 | 注入联调 | 手势→视频切换端到端跑通 | 未开始 |

## 11. 决策记录（ADR）

| # | 决策 | 放弃了什么 | 理由 |
|---|---|---|---|
| 1 | 用静态手势而非滑动 | 滑动的「手感自然」 | 滑动要求四项判据同帧成立，手一转侧就失效；静态手势失败模式更温和 |
| 2 | 触发后锁定 | 连续快速切换 | 不锁定就会「切完手一放又切回来」，这是实测暴露的最高频误触 |
| 3 | 朝向不参与触发 | 严格区分手心/手背 | 朝向判定受左右手与镜像影响，判错即全错；指型本身已有区分度 |
| 4 | 快进做成倍速循环 | 直接跳 10 秒 | 循环可反复验证、粒度可控；跳转会与「比 1」语义重叠 |
| 5 | 五指张开要求「张开」 | 只要四指伸直即可 | 平掌太常见，摊手、伸懒腰都会触发暂停 |
| 6 | 新增右上角快捷开关 | 只保留快捷键 | 快捷键需要记忆，且开会前找不到开关是致命体验问题 |
